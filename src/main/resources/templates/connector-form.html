X (Twitter) Bearer / OAuth 2.0 配置

📖 获取教程：如何拿到 X 的 Bearer Token / OAuth 2.0 Token
方式一：App-Only Bearer Token（最快，适合只读搜推文 / 查公开用户）
  1. 登录 X 开发者后台：developer.x.com/en/portal/dashboard，创建或打开你的 Project & App。
  2. 进入该 App 的 Keys and tokens 标签页。
  3. 在 Authentication Tokens → Bearer Token 区域点击 Generate（或 Regenerate）。
  4. 复制生成的长字符串（通常以 AAAA... 开头），直接粘贴到上方输入框保存即可。
权限说明：App-Only Bearer Token 仅支持读取公开数据（如搜索推文、查用户信息），无法代表个人账号发推，也不支持调用 /2/users/me（本平台“测试”按钮会自动改测公开端点 /2/users/by/username/X）。
方式二：OAuth 2.0 User Access Token（PKCE，支持以用户身份发推与读取）
  1. 进入 App 的 Settings → User authentication settings，点击 Set up / Edit。
  2. App permissions 选择 Read and write；Type of App 选择 Web App, Automated App or Bot（或 Native App）；填写 Callback URI（如 http://localhost:8080/callback）与 Website URL 并保存。
  3. 切回 Keys and tokens → OAuth 2.0 Client ID and Client Secret，记录 Client ID 与 Client Secret。
  4. 浏览器访问授权链接获取 code（携带 PKCE code_challenge，示例 Scope：tweet.read tweet.write users.read offline.access）：
    https://x.com/i/oauth2/authorize?response_type=code&client_id=<CLIENT_ID>&redirect_uri=<CALLBACK_URI>&scope=tweet.read%20tweet.write%20users.read%20offline.access&state=muse&code_challenge=<CHALLENGE>&code_challenge_method=S256
  5. 同意授权后从回调地址取出 code，调用 POST https://api.x.com/2/oauth2/token（grant_type=authorization_code + code + code_verifier）换取 JSON 中的 access_token，粘贴到上方输入框。
选型建议：OAuth 2.0 User Access Token 默认 2 小时过期（需配合 refresh_token 定时续期）。如果你希望一次配置长期自动发推，建议直接在上方将“连接认证方式”切换为 OAuth 1.0a (HMAC-SHA1)。

X (Twitter) OAuth 1.0a 密钥配置（自动 HMAC-SHA1 签名）

📖 获取教程：如何拿到 X 的 OAuth 1.0a 四个密钥（推荐长期发推）
  1. 登录 X 开发者后台：developer.x.com/en/portal/dashboard，创建或打开你的 Project & App。
  2. 先配置读写权限（关键步骤）：进入 App 的 Settings → User authentication settings，点击 Set up / Edit：
    • App permissions：选择 Read and write（若需私信选 Read and write and Direct message）。
    • Type of App：选择 Web App, Automated App or Bot。
    • Callback URI / Website URL：填入合法网址（如 http://localhost:8080/callback）后点击 Save。
  3. 切回 App 的 Keys and tokens 标签页，在 Consumer Keys 区域点击 Regenerate（或 View）：
    • 复制 API Key → 填入上方 API Key (Consumer Key)
    • 复制 API Key Secret → 填入上方 API Secret (Consumer Secret)
  4. 向下滚动到 Authentication Tokens → Access Token and Secret，点击 Generate / Regenerate：
    • 复制 Access Token → 填入上方 Access Token
    • 复制 Access Token Secret → 填入上方 Access Token Secret
    • 确认该区域提示为 Created with Read and Write permissions。
  5. 保存后在控制台点击 测试（验证 GET /2/users/me 返回 200 即表示四元组可用）。
常见踩坑：如果之前在只读状态下生成过 Access Token，之后再改权限，旧 Token 依然没有写权限（发推会报 403 Forbidden）。修改权限后必须重新点击 Regenerate 生成新的 Access Token 与 Secret。
推荐理由：OAuth 1.0a 凭证不会自动过期（除非你手动重置），本中转站已内置 HMAC-SHA1 自动签名，最适合 Muse 长期稳定发推和查账号。

X (Twitter) 网页 Cookie 配置（普通用户免开发者账号）

📖 获取教程：普通用户如何从浏览器获取 X 的 auth_token 和 ct0
  1. 在桌面浏览器（Chrome / Edge / Arc 等）打开并登录 https://x.com（无需申请开发者账号）。
  2. 按 F12（macOS 按 Cmd + Option + I）打开开发者工具，切换到顶部 Application（应用） 标签页。
  3. 在左侧菜单依次展开 Storage → Cookies → https://x.com。
  4. 在右侧列表中找到名称为 auth_token 的一行，双击并复制其 Value → 填入上方 auth_token。
  5. 继续找到名称为 ct0 的一行，双击并复制其 Value → 填入上方 ct0（中转站会自动同步写入 Cookie、x-csrf-token 及动态计算的 x-client-transaction-id 请求头，并在遇 404 时自动刷新重试）。
  6. 保存后在控制台点击 测试（验证 GET /i/api/1.1/account/settings.json 返回 200 即表示登录态有效）。
注意事项：
• 网页 Cookie 属于 X 内部非官方会话接口，请控制调用频率避免触发风控；若在浏览器点击退出登录或修改密码，旧 auth_token 会立即失效，需重新复制。
• 中转站会自动从 X 网页脚本动态解析最新的 GraphQL queryId 与特性开关（遇 404 时自动刷新重试）；若需手工固定或热覆盖，可在浏览器 Network（网络） 面板查看 /i/api/graphql/<queryId>/CreateTweet 并填入上方“自定义 GraphQL Query IDs”（优先级最高）。
默认端点：该模式下“自定义 API Base URL”留空默认请求 https://x.com；在通用转发接口 POST /api/relay/x/{profileId}/request 中可直接透传任意 /i/api/... 路径。

Telegram Bot API 配置

📖 获取教程：如何拿到 Telegram Bot Token 与 Chat ID
  1. 创建机器人拿 Token：在 Telegram 中搜索官方账号 @BotFather，发送 /newbot，依次输入机器人显示名称和以 bot 结尾的用户名，复制返回的 HTTP API Token（形如 123456789:ABCdef...）填入上方 Bot Token。
  2. 获取私聊 Chat ID：先打开刚创建的机器人发送一条任意消息（如 /start），保存本配置后到 在线调试 调用 GET /updates，从响应的 result[].message.chat.id 中即可拿到数字 ID。
  3. 获取群组 / 频道 Chat ID：将机器人拉入群组或设为频道管理员，在群里发一条消息后同样调用 GET /updates，超级群组/频道的 Chat ID 通常以 -100 开头。
网络提示：若部署服务器无法直连 api.telegram.org，可在下方“通用网络与超时参数”配置 HTTP 代理或反代 Base URL。

SSH 远程服务器配置

📖 配置说明：SSH 密码认证注意事项
  1. 确认目标服务器已开启 SSH 服务（默认端口 22），且 /etc/ssh/sshd_config 中 PasswordAuthentication yes 已启用。
  2. 建议为 Muse 创建专用低权限系统账号，并在上方“允许命令前缀白名单”中限制可执行命令（例如 ls,df,uname,uptime,docker ps）。
安全建议：生产环境优先推荐使用 SSH Private Key 私钥认证，并在服务器禁用密码登录。
📖 获取教程：如何生成并配置 SSH 私钥（支持 Ed25519 / RSA / ECDSA）
  1. 生成专用密钥对：ssh-keygen -t ed25519 -C "muse-relay" -f ~/.ssh/muse_ed25519（不需要口令可直接回车留空）。
  2. 把公钥部署到目标服务器：ssh-copy-id -i ~/.ssh/muse_ed25519.pub 用户名@服务器IP（或手动将 muse_ed25519.pub 追加到目标机 ~/.ssh/authorized_keys，并执行 chmod 600 ~/.ssh/authorized_keys）。
  3. 查看并复制私钥全文：cat ~/.ssh/muse_ed25519，将包含 -----BEGIN ... PRIVATE KEY----- 与 -----END ... PRIVATE KEY----- 的完整内容粘贴到上方私钥框；如设置了口令则填入 Passphrase。
